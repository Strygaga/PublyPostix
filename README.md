# PublyPostix

> **Распределённый шлюз и оркестратор для автопостинга контента в соцсети прямо из Telegram.**

Проект построен по принципам System Design и **12-Factor App**: оркестратор работает как **Stateless**-сервис, а PostgreSQL служит **единым источником истины** для конечного автомата (FSM) и журнала всех публикаций.

---

## 🏗 Архитектура (System Topology)

Вся система разделена на три слоя по шаблону **«Шлюз — Ядро — Адаптеры» (Gateway — Core — Adapters)**:

│                                                                                       │
│  • Event Ingestion Gateway: парсинг команд (/start), сигналов (RPC) и контента        │

## 💡 Ключевые инженерные решения

### 1. Распределённый FSM поверх PostgreSQL

Воркеры n8n не держат контекст пользователя в памяти. Всё текущее состояние (`current_state`) и рабочий буфер сессии (`draft_data` в JSONB) живут в таблице `users`. Любые навигационные действия — сбросы, отмены, переходы — выполняются атомарно в одной транзакции через SQL CTE, так что зависших сессий просто не бывает.

### 2. Гонки при приёме альбомов (Batch Leader Election)

Когда пользователь отправляет альбом, Telegram присылает параллельные вебхуки на каждый медиафайл — и у всех один и тот же `media_group_id`. Чтобы не было гонки, реализован выбор лидера пачки:

* Элементы копятся в JSONB-массиве, а монотонный счётчик `received_count` инкрементируется.
* Небольшая буферизация по времени и выборка максимального `current_max_seq`.
* Интерфейс сборки карусели отрисовывает строго один воркер — в чате не появляется дублей.

### 3. Двухуровневый пайплайн каруселей в Meta Graph API

Чтобы опубликовать карусель в Instagram, сначала нужно создать дочерние элементы (`is_carousel_item=true`), связать их в родительский контейнер (`media_type=CAROUSEL`) и только потом выпускать:

* Пропорции каждого слайда валидируются независимо: если один слайд не прошёл — остальные всё равно публикуются (мягкая деградация).
* Видеослайды транскодируются асинхронно — работает неблокирующий `Polling Loop` с предохранителем по таймауту (`Circuit Breaker`).

### 4. Авторизация VK ID по OAuth 2.1 (RFC 7636 PKCE)

Интеграция с VK ID сделана по современному стандарту — с защитой от перехвата авторизационного кода:

* Генерируется криптографический `code_verifier`, от которого на лету считается SHA-256 (`code_challenge`) в Base64URL.
* Сессия пробрасывается через `draft_data` с привязкой к конкретному устройству (`device_id`).
* Обмен кода на `access_token` и `refresh_token` с автоматической упреждающей инвалидацией.

### 5. Идемпотентность и честный аудит (Audit Trail)

Каждая публикация пишется в таблицу `publications` с уникальным `idempotency_key` и подробным `media_payload` в JSONB. Пользователь получает уведомление об успехе **только после того, как запись попала в базу** — не раньше.

## 🛠 Стек технологий

* **Оркестрация:** n8n (Self-hosted в Docker, архитектура Sub-workflows).
* **Хранение данных:** PostgreSQL 16 (JSONB, атомарные CTE, триггеры, B-Tree индексы).
* **Инфраструктура:** Docker, Docker Compose, 12-Factor App (`.env`).
* **Внешние API и протоколы:**
  * Telegram Bot API (RPC-маршрутизация `domain:action:param`)
  * Meta Graph API v21.0 (Instagram Reels, Feed Posts, Stories, Carousels)
  * VK ID API (OAuth 2.1, PKCE, Device Session Binding)
  * REST API, Webhooks, Postman.

---

## 📊 Схема базы данных (Schema Overview)

Схема версионируется в файле `docs/schema.sql` (Single Source DDL):

* **`users`:** профили Telegram-пользователей, роли, статус, текущее состояние FSM (`current_state`) и буфер контекста (`draft_data` в JSONB).
* **`connected_platforms`:** активные подключения, маскированные аккаунты, OAuth-токены, сроки жизни (`expires_at`) и выданные права (`scopes` в JSONB).
* **`publications`:** журнал всех релизов — платформа, тип контента, `media_payload` в JSONB и статус (`published`, `failed`).

## 🚀 Локальный запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/ваш-логин/PublyPostix.git
   cd PublyPostix
   ```

2. **Настройте переменные окружения:**
   ```bash
   cp .env.example .env
   # Заполните TELEGRAM_BOT_TOKEN, META_* и VK_* ключами в файле .env
   ```

3. **Поднимите стек:**
   ```bash
   docker compose up -d
   ```

4. **Импортируйте сценарии в n8n:**
   * Откройте n8n по адресу `http://localhost:5678`.
   * Импортируйте главный сценарий `workflows/publypostix_core.json` и адаптер `workflows/[Adapter] Instagram Publisher.json`.
   * Активируйте воркфлоу.
